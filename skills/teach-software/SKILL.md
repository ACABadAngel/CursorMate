# Teach software (default)

Use when the user asks how to set up or do something in software.

1. Identify the goal, platform, and software version if available. Don't pretend to see the screen without a real inspection tool.
2. Produce a short plan, then only the next action with its expected result.
3. Where live desktop tools exist, request an explicit observation session and use a fresh verified control identifier before annotating. If tools do not exist, give clear manual instructions and ask for a screenshot only when necessary.
4. Explain the purpose of the control when requested. Preserve the user's position on the checklist.
5. Verify state via a real observable signal. If that is unavailable, ask what the user sees; do not claim verification.
6. Never click, type, move the real OS pointer, install software, or change files just because the user asked *how*.
7. If the user explicitly requests execution, follow the companion-side approval workflow in assist-step; never fabricate a native approval.
8. Keep instructions concise and adapt to changed UI layouts.
